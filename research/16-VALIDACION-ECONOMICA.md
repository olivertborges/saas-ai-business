# 16 — Validación económica

## Objetivo

Determinar si los problemas identificados en las entrevistas tienen suficiente valor económico como para justificar el pago recurrente por una solución.

Esta fase busca responder:

> ¿Qué dinero, tiempo y recursos está utilizando actualmente un negocio para resolver estos problemas?

Y posteriormente:

> ¿Existe una oportunidad real para sustituir, reducir o mejorar parte de ese gasto mediante nuestro producto?

La siguiente ronda debe volver sobre algunos entrevistados y obtener números concretos.

Preguntas principales:

### Tiempo

- ¿Cuántas horas por semana dedicas aproximadamente a esto?

### Alternativas

- ¿Lo haces tú?
- ¿Lo elimina el negocio?
- ¿Contratas otra persona?
- ¿Utilizas otra herramienta?

### Prioridad

- De todo lo que haces actualmente, ¿qué eliminarías primero si pudieras?
- ¿Qué tarea te gustaría dejar de hacer completamente?
- ¿Qué tarea seguirías queriendo controlar personalmente?

# 6. Validación de disposición a pagar

La disposición a pagar debe investigarse de forma progresiva.

No comenzar preguntando:

> “¿Pagarías X por nuestro SaaS?”

Primero debemos entender:

1. qué problema tiene;
2. cuánto tiempo consume;
3. cuánto dinero cuesta actualmente;
4. qué solución utiliza;
5. cuánto paga por esa solución;
6. qué resultado obtiene;
7. qué cambiaría si tuviera una alternativa.

Después podremos investigar precios concretos.

---

# 7. Diferenciar intención de compra de comportamiento

Una afirmación como:

> “Si existiera, lo pagaría.”

es una señal útil, pero débil.

Debe diferenciarse de:

- actualmente paga por una solución;
- está buscando una alternativa;
- solicita una demostración;
- acepta probar un prototipo;
- proporciona datos reales;
- acepta una prueba piloto;
- acepta pagar;
- continúa pagando.

La evidencia económica aumenta cuando pasamos de declaraciones hipotéticas a comportamientos reales.

# 9. Métricas económicas que necesitaremos posteriormente

Cuando exista suficiente información podremos estimar:

### Coste actual del problema

`coste de software + personas + publicidad + tiempo + oportunidad perdida`

No necesariamente todos estos componentes deberán sumarse directamente; se analizarán por separado para evitar doble conteo.

### Coste de nuestra solución

`IA + infraestructura + almacenamiento + integraciones + soporte + otros costes variables`

### Margen bruto

`ingreso - costes variables`

### Retención

Necesitaremos observar:

- permanencia;
- cancelaciones;
- frecuencia de uso;
- funciones utilizadas;
- valor percibido.

### CAC

Coste de adquisición de cliente.

### LTV

Valor económico generado durante la relación con el cliente.

Estas métricas pertenecen a una fase posterior y no deben inventarse antes de disponer de datos.

---

# 10. Riesgos económicos

Debemos investigar especialmente:

- que el problema sea importante pero no suficientemente caro;
- que los negocios quieran la solución pero no puedan pagarla;
- que prefieran contratar personas;
- que solo utilicen el producto durante meses de alta actividad;
- que cancelen durante meses malos;
- que los costes de IA sean demasiado altos;
- que las integraciones tengan costes adicionales;
- que el soporte requerido sea demasiado elevado;
- que el producto termine funcionando como una agencia y no como SaaS;
- que el ahorro de tiempo no se traduzca en disposición a pagar.

---

# 11. Objetivo de la siguiente etapa

Antes de definir precio o modelo comercial debemos conseguir evidencia suficiente para responder:

1. ¿Quién tiene un problema económicamente importante?
2. ¿Qué problema concreto genera el mayor coste?
3. ¿Cuánto cuesta actualmente resolverlo?
4. ¿Quién paga actualmente?
5. ¿Qué alternativa utiliza?
6. ¿Qué resultado obtiene?
7. ¿Qué parte estaría dispuesto a automatizar?
8. ¿Qué parte necesita supervisar?
9. ¿Qué comportamiento demuestra intención de compra?
10. ¿Qué precio podría tener sentido según el valor y los costes?

---

# 12. Regla de decisión

No se seleccionará un precio, segmento ni MVP basándose únicamente en:

- opiniones hipotéticas;
- entusiasmo;
- una entrevista;
- cifras inventadas;
- precios de competidores sin contexto;
- preferencias personales.

La decisión deberá apoyarse en:

**Evidencia → Problema → Coste → Valor → Comportamiento → Validación**
